# ADR-0007 — action self-sufficiency: the 8th rung, one refined bare-reference check,
one-command fill dispatch, and A3/B4 retirement from technical-spec.md

**Status:** Accepted (v27.8.0)
**Supersedes:** none (extends ADR-0006's action-thread reshape; retires the A3/B4 half of
ADR-0006's "unchanged" § 5 sections and the v26.0.0 A3/B4 decision recorded in the SKILL.md
history this ADR does not restate)
**Cites:** ADR-0006 (action-first spine, `RUNG_LABELS`, the fill-pending degradation window),
ADR-0005 (a gate's severity label is not its teeth), ADR-0004 (the audience split)
**Date:** 2026-08-25

---

## Context

ADR-0006 gave `technical-spec.md` an action-keyed spine but left three gaps a dev reading one
`#### A<n>` block still had to leave the block to close: no rung named the state transition an
action's own write caused (and no detector noticed the absence); a business/decision/state/
algorithm/integration/discovery code could sit bare in the H4 context line with a citation
existing only in `§ 4.4 Shared Foundation`, several hundred lines away; and `--migrate --only
action-thread` composed the shape and then stopped at exit 4 printing `[HANDOFF]`, with nobody —
no script, no CI job — dispatching the researcher fill pass that `needs_llm_fill` promised. A
fourth, unrelated gap sat next to these: A3 (`## Source Walkthrough`) and B4 (`## DB Impact per
Event`) duplicated the Result rung's own DB-write statement three ways across technical-spec.md
(Result rung prose, A3's narrative call hierarchy, B4's per-table row), for a corpus where B4
turned out to add zero net-new citation coverage once measured correctly (§ "A3/B4 retirement"
below).

This ADR's decisions were sealed BEFORE measurement (plan.md, 2026-08-24) and then substantially
amended by five corrections found on disk (X1–X5) and ten post-measurement decisions (D8–D17)
found while building against the real 43-feature corpus. Both sets are recorded here in full,
per the plan's own instruction that a sealed design's assumptions are checked against
measurement, not defended against it.

---

## Decision 1 — `State` is the 8th rung, anchored on a document-level structural fact

`RUNG_LABELS` becomes `("Who", "FE", "Request", "BE", "Rule", "Result", "State", "Source")`.
The rationale for the rung shape itself, the `**State** · ` vs `**Source:**` separator
distinction, and the SM-edge-join alternative that was measured and dropped (12.5% join rate,
D9) are recorded in ADR-0006's own "self-sufficiency v27.8" addendum and are not repeated here.

**What this ADR adds that the addendum does not cover: the anchor was re-derived once, on
measurement (D8).** The sealed design anchored `state_rung_missing` on "this action's own § 2
`Codes` cell carries an `SM-###` token AND `Writes` is non-`—`" — measured firing population: **1**
action in the entire 43-feature corpus (phase 00's HALT, `M7 = 1` against a floor of 10). Root
cause: SM-### codes sit almost entirely on the cross-cutting `A0` row (16 of ~21 corpus-wide
citations), not on the action rows that actually write. The anchor was re-derived to
**document-level**: "the feature carries a real `### … (SM-###)` heading block **AND** this
action's own § 2 `Writes` cell is non-`—`" — no longer requiring the action to cite the SM code
itself. Measured population: **95** actions across **14** features. This is not prose-sniffing
(D3, ADR-0006, unchanged): the SM block's existence is a structural fact the parser reads off a
heading regex, never an inferred transition from a method name. Precision is accepted at
~40-60% (not every DB write inside an SM-modelled feature is itself a state transition —
`updated_at` bumps, join rows, log appends are not), same bar as `crosscutting_unlabelled`'s
existing warning severity.

## Decision 2 — `action_ref_unglossed`: one refined check, six families, ships instead of the
naive one

Two predicates were built and measured side by side, not one designed and assumed correct:

| Predicate | Definition | Corpus count | Precision |
|---|---|---|---|
| Refined (shipped) | flags a code only if **no** occurrence anywhere in its `#### A<n>` block carries a clearing gloss (≥12 non-code alphanumeric characters on that occurrence's line) | 21 (BR 20, DEC 1) | 21/21 hand-verified genuine (100%) |
| Naive (rejected) | flags any bare occurrence in the H4 context line alone, ignoring whether the same code is glossed elsewhere in the block | 99 | 21/99 ≈ 21% |

The naive predicate is the same low-precision shape ADR-0005 already rejected for v27.6.0's
feature-naming rule (~7-10% there) — this repo does not ship a second instance of a check whose
false-positive rate would train an operator to ignore its output. `action_ref_unglossed` ships
at `warning`, spans BR/DEC/SM/ALG/INT/DISC (FR/US excluded — those are cited, not carried, by an
action's own rungs), and degrades under the same fill-pending window `state_rung_missing` and
`diagram_required_missing` already use.

## Decision 3 — `--migrate --only action-thread` composes AND fills, one command

The `a3-b4` fill-guard/citation-target machinery (`evaluate_fill`, `check_a3_citation_label`,
`check_citation_targets`, `strip_sections`, `_BRACE_RE`) is cloned for `action-thread`'s own
rungs rather than reused directly — the shapes differ (a rung is not an A3/B4 section) but the
wave-gate discipline is identical. The orchestrator (never a subprocess — a subprocess holds no
Task tool, D4/plan.md) dispatches a bounded-wave researcher fill pass per feature, reading
`pending-breakdown.json`'s per-rule_id counts rather than a grep-derived guess, and the wave gate
reverts any write outside the dispatched unit's own `allowed_actions` set (D13/D14 below).
Killing the command mid-run and re-running it resumes without duplication — artifact-derived
idempotency (AD-1), never a marker file, the same discipline `cap-map`'s rollback already
established.

## Decision 4 — A3/B4 retirement from technical-spec.md: the correct justification

**A3 (`## Source Walkthrough`) and B4 (`## DB Impact per Event`) leave technical-spec.md's
target shape.** `check_db_impact()` and its four `db_impact.*` rule_ids are deleted outright,
with their tests. `check_source_walkthrough`/`_section_body`/`A3_HEADING` are untouched and
remain the only gate — but `validate_reading_guide_db_impact.validate()` no longer walks
`features/*/technical-spec.md`; A3 stays fully live on `screens/*/spec.md` only.

**The justification, stated in the words this ADR was told to use:** *after deletion there is
nothing left to check.* Never *"something else already checks it"* — that second sentence is
false and was verified false before this decision was accepted:
`validate_source_citations.py`'s `CITATION_RE` is anchored on the literal `**Source:**` prefix
(`r"\*\*Source:\*\*\s+\`?([^\`\n:]+):(\d+)(?:-(\d+))?\`?"`); a B4 table cell is a bare backtick
token inside a `|`-delimited markdown cell with no `**Source:**` text anywhere on its line — this
regex structurally cannot and does not match it (verified by grep against the live regex, phase
05). Nothing downstream inherits B4's coverage. Retirement is justified because there is nothing
left to check, not because coverage moved elsewhere.

**Measured before deciding, not assumed:** re-tabulated on the migrated-snapshot corpus, B4 carries
**279 rows / 334 citation line-segments (43 features)**, of which **0** fail to already appear in
their owning action's own `**Source:**` rung (any hop). The 5-orphan figure in the sealed design
was itself a measurement artifact — a script bug that treated comma-joined line-lists inside one
backtick (`` `file.rb:17,34-40` ``) as unparseable and miscounted them; the corrected parser found
0 orphans over the corrected, larger denominator (334, not 260). Fold-vs-record is moot at zero
orphans: there is nothing to fold. **Decision: (b) Record, no `[INFERRED]` replacement.** A
scratch-only predicate for the alternative (flag a writing action whose Source rung carries
neither a citation nor `[INFERRED]`) measured **0 of 182** writing actions would fire — the
invariant it would enforce is already 100% satisfied without new code; building it violates YAGNI.
The one-line CHANGELOG record this decision produces:

> B4 (`## DB Impact per Event`) retired without a citation-rescue fold: 0 of 334 B4 citation
> line-segments (279 rows, 43 features) failed to already appear in their owning action's own
> `**Source:**` rung, measured on the 260824 migrated-snapshot corpus.

**What volume-zero does NOT mean: a granularity loss, stated rather than silently absorbed.** B4
cites per **(action, table)** pair — one row per table an event writes. The Source rung cites per
**action**, as one chain shared across every table that action touches. Worked example, real
corpus: `F034_MarketplaceBootstrap` A2 writes **11 distinct tables** behind a single 12-hop
`**Source:**` chain carrying the same citations (0 orphans) but no table labels — the reader can
only recover which hop wrote which table by assuming hop order tracks Result's write-order, a
convention that already partially breaks inside this same example (one hop packs two file
citations for a single table while every other table gets exactly one hop). **45 of 379 action
rows (11.9%)** write ≥2 distinct tables and are exposed to the same loss after B4's deletion —
recoverable only by re-reading the source the way the original fill pass did, not by anything
that survives B4's removal. This is disclosed as a real, accepted cost, not covered by
`check_source_walkthrough`, not covered by the Source rung, and not covered by anything new this
release ships.

## Standing requirement — `REOPEN_RULE_IDS` registration is the ONLY way a detector reopens a
file

**`needs_reopen(feature_dir, root)` is, and must remain, `filter _check_feature_dir's issues by
rule_id in REOPEN_RULE_IDS`. Never a second predicate.** This repo's checks are batched,
multi-rule_id functions (`_check_action_thread`, `_check_rule_bins_and_diagrams`) with no
per-rule `would_fire` primitive; three independently-implemented reopen predicates for three
different detectors would each have to reconstruct that filter by hand, and any two of them
disagreeing about what "pending" means is exactly the failure class this release exists to close
(X5, below). Consuming the validator's own output makes detector/firing divergence structurally
impossible rather than merely tested.

**Registering a new detector is a one-line append to `REOPEN_RULE_IDS`.** This release added two:
`FeatureSpec.state_rung_missing` (phase 01/02) and `FeatureSpec.retired_section_present` (phase
08, the deletion-direction twin — it is what now flags a technical-spec.md still carrying either
retired A3/B4 heading, driving the one-shot mechanical strip through this SAME mechanism). Six
members total as of this release.

**A bare string cannot be registered — it needs a real rule_id behind it.** Requirement 2's
original phrasing ("register a 'carries A3 or B4' term") could not work as written: `needs_reopen`
filters by `rule_id`, so a term with no validator check behind it matches nothing and silently
never fires. The fix is always to build the real check first (`FeatureSpec.retired_section_present`
here), then register its rule_id — never to special-case a string into `_is_pending`/
`count_pending`/`run()` directly, and never to skip building the check because "it's just a
heading name, surely that's enough."

**A detector that cannot reopen a file is a warning with no remediation path.** That is exactly
what C1 was before phase 02 (see X5) — say it in those words, not softened, because a validator
that reports a defect nobody's tooling can act on trains operators to ignore the validator, the
same failure this ADR's A3/B4 justification (above) is careful never to repeat in the opposite
direction.

## Consequences

- **`_spec_constants.A3_HEADING`/`B4_HEADING` are not deleted** — they remain the single source of
  truth for the literal heading text, now consumed by `FeatureSpec.retired_section_present`
  (detecting a leftover), `_a3_fill_guard_lib`/`_a3_citation_target_lib` (A3-only, screens), and
  the legacy-shape extractors in `_feature_sot_extract_lib.py`/`_feature_sot_technical_lib.py`
  (still needed to read a pre-migration 5-bucket corpus). Neither literal was ever a member of
  `REQUIRED_H2_TECH_THREAD`'s exact-order check (Decision 2, ADR-0006's predecessor decision,
  unchanged) — so this release's retirement touches zero `_bounds()`/`_bounds_at()` order-gating
  code; the C15 heading-literal audit (release report) accounts for every literal this release
  DID move.
- **`db_impact.*` (4 rule_ids) retired with their 11 tests.** `reading_guide.*` (3 rule_ids)
  UNCHANGED in logic, narrowed in scope (technical-spec.md no longer walked). No rule_id lost
  meaning without a replacement being named: `FeatureSpec.retired_section_present` is the
  deletion-direction functional successor for "does technical-spec.md still carry either retired
  heading."
- **Six-member `REOPEN_RULE_IDS`** as of this release: `state_rung_missing`,
  `action_ref_unglossed`, `diagram_required_missing`, `rule_bin_misplaced` (pre-existing, ADR-0006),
  `crosscutting_unlabelled` (pre-existing), `FeatureSpec.retired_section_present`. Any future
  addition follows the standing requirement above — a one-line append, never a special case.
