## Design decisions made (spec was ambiguous, settled before coding)

1. **`viewer.ts` returns a third field, `userId`.** Step 2 says "return only those two fields; the
   user object stays here." Literally followed for `KudosBoardViewModel.viewer` (only
   `isAuthenticated`/`sunnerId` ever land there). But `kudos_likes.user_id` references
   `auth.users(id)` directly (ratification #4), so `fetchViewerLikes()` and the action both need
   the raw auth uuid — not the full `User` object (email/metadata/identities), which genuinely
   never leaves `viewer.ts`. Recording this because it's a real interpretation call, not a silent
   deviation.
2. **`resolveSidebarSunnerId()`'s "auth_user_id IS NULL" fallback is not unique in the current
   seed** — all 9 seeded `sunners` rows have `auth_user_id` NULL (no trigger links a freshly
   signed-up e2e user to one). Resolved with `order by id asc limit 1`, which deterministically
   picks the frame viewer (id=1, inserted first, the only row whose counters are the frame's
   `25`s) — verified against the DB (see below). Flagging this since a future seed change that
   inserts a *new* unlinked row before id=1 would break it; the id-1 row is the intended anchor.
3. **Sidebar's `kudosReceived`/`kudosSent`/`heartsReceived` are derived from the already-fetched
   `fetchKudos()` array, not a separate query** — reuses data already in memory instead of 3 more
   round trips, keeping the NFR's "one board read per request" intent. `fetchSidebarBoxCounts()`
   only queries the two stored counters (`secret_box_opened/unopened_count`). Badge `receivedCount`
   is computed the same way, once, from the full array — not a per-card query.
4. **`SpotlightBoard`'s `total` prop isn't in the frozen `KudosBoardViewModel`** (checked
   `app/kudos/_components/spotlight-board.tsx:34-40` — it already expects a separate `total: number`
   prop, matching test-contract's "Overridden" ruling that 388 is seeded data, not a view-model
   field the phase-01 contract anticipated). Exposed as a second export, `getSpotlightTotal()`,
   rather than patching the frozen `view-model.ts` (out of scope, "escalate, don't patch
   unilaterally").
5. **Ticker's `HH:mmAM/PM` format has no helper in frozen `derive.ts`** (it only has the
   `HH:mm - MM/DD/YYYY` format for `sentAtLabel`). Added a small private `formatTickerTime()` in
   `board-data.ts` at the same fixed UTC+7 offset idiom, not a modification to `derive.ts`.
