## Workaround (tracked)

WSL2 machine has no passwordless `sudo` (confirmed: `sudo -n` fails, `dangerouslyDisableSandbox`
bash mode makes no difference — it's a real password prompt, not a sandbox artifact), so
`npx playwright install --with-deps chromium` cannot run `apt-get install`. Headless Chromium
failed to launch with `libnspr4.so: cannot open shared object file` (also needed `libnss3`,
`libasound2t64` — everything else Chromium needs was already present on this box).

Fix: downloaded the three `.deb` packages with `apt-get download` (no root required) and extracted
them with `dpkg-deb -x` into `.playwright-libs/` at the repo root — never committed
(`/.playwright-libs/` added to `.gitignore`). `playwright.config.ts` prepends that directory to
`LD_LIBRARY_PATH` **only if the directory exists** (`fs.existsSync` guard), so this is a no-op on
any machine that already has the system libs (or where `--with-deps` succeeded) and does nothing
destructive to `process.env` otherwise. This is a machine-local, environment-level workaround, not
application code — no file outside the phase's ownership list was touched to make it work.

If this repo is cloned onto a fresh WSL2 box without root either, the same three commands
reproduce the fix:
```
apt-get download libnspr4 libnss3 libasound2t64
dpkg-deb -x <each .deb> .playwright-libs
```
